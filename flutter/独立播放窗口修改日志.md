## 功能说明

- **播放流程**：详情页点击播放 → 引擎照常解析出 playUrl（含磁力/DRM 处理、UA/Header 修正）→ 桌面端且开关开启时，把 vodName/标题/集数/URL/headers/解码模式/画面比例/音量/倍速通过 `WindowController.create` 传入新窗口 → 独立窗口自建 media_kit(MPV) 播放器渲染。窗口已存在时直接切集（复用窗口，不重复弹窗）。
- **主窗口空闲区**：独立窗口模式下，主窗口视频区点击/双击 = 把播放窗口调到前台；集数列表照常切换集数。
- **独立窗口 UI**：顶部标题+关闭、底部播放/暂停、进度条（拖动即 seek）、时间显示、音量、5 秒无操作自动隐藏；键盘：空格=播放暂停、←/→=快退/快进 10 秒、Esc=关闭。
- **跨窗通信**：`kotv_playback`（主→子：play/close）+ `kotv_playback_host`（子→主：closed/error）。窗口创建失败自动回退内嵌播放，不会黑屏。
- **开关**：设置 → 播放器 →「独立播放窗口」（桌面端可见；缺省开启，键 `popupPlayer`：'true'/'false'）。

## v2 修复（2026-10-29，实机反馈）

用户实机反馈 3 个问题，已全部修复：

1. **点关闭（×/Esc）连主窗口一起退出** — 根因：子窗口里调用了 `windowManager.destroy()`，其实现是 `PostQuitMessage(0)`，打在**主消息循环**上（desktop_multi_window 子窗口与主窗口共享消息循环），导致整个进程退出。修复：子窗口**禁用 destroy / setPreventClose**，关闭只走 `windowManager.close()`（发 SC_CLOSE 只销毁子窗口本身）；播放器释放后由主窗口 host 回调复位。
2. **弹出后主界面无法操作 / 关闭后主界面卡死** — 根因同上（destroy 打崩主循环前主窗口已不可交互）。修复后子窗口对 window_manager 的调用收敛为"自身窗口的显示层"（ensureInitialized/setTitle/setMinimumSize/center，post-frame 执行确保句柄是本窗口），并加 `onWindowsChanged` 兜底：窗口被系统直接关闭（列表消失）时自动通知主窗口复位。
3. **独立播放窗口内没有选集** — 新增：底部控制条加「选集」按钮 → 弹出集数面板（滚动 Wrap、当前集高亮）→ 点击后通知主窗口（host channel `switchEpisode`）→ 主窗口解析新集 URL 并切集回传，子窗口显示"切换中…"（10s 超时兜底）。

### v2 关键文件
- `flutter/lib/desktop/playback_window.dart`：子窗口生命周期收敛（无 destroy/setPreventClose）+ 选集 UI + onWindowsChanged 兜底 + `onSwitchEpisode` 回调
- `flutter/lib/screens/detail_screen.dart`：注册 `PlaybackWindow.onSwitchEpisode` → `_playAt(idx)` 切集
- 验证：`flutter analyze` 0 error；`flutter test` 26/26 通过

## v3 修复（2026-10-29，关闭彻底修复）

v2 交付后用户实机反馈：**两个关闭（系统 ×、窗口内 ×）仍然都不正常**——系统 × 会把主窗口一起退出；窗口内 × 后主界面不可操作。

### 根因（本次彻底定位）

flutter_windows 引擎对窗口的 `WM_CLOSE` 默认处理是走**进程级全局 RunLoop 的 `PostQuitMessage`**。desktop_multi_window 的 Windows 子窗口与主窗口共享同一个消息循环，所以**任何让子窗口 WM_CLOSE 到达引擎的关闭路径，都会把主窗口连同整个进程一起退出**：

- 系统标题栏 × → WM_CLOSE → 引擎默认处理 → 全退；
- `window_manager.close()`（v2 方案）→ 发 `SC_CLOSE` → WM_CLOSE → 引擎 → 全退；
- `window_manager.destroy()`（v1 方案）→ 直接 `PostQuitMessage(0)` → 全退。

官方 demo（video_player_window）之所以"正常"，是因为它是**单业务窗口应用**：一次只开一个窗口，进程退出 == 窗口关闭，表现无感。对"主窗口 + 子窗口共存"的应用，这套关闭链完全不可用。

### 修复方案：关闭绕过 WM_CLOSE，原生直接销毁子窗口

1. **原生通道**（`flutter/windows/runner/flutter_window.cpp`）：子窗口创建回调里注册 `kotv_playback_native` MethodChannel，方法 `destroySelf` → `::DestroyWindow(::GetAncestor(子窗口句柄, GA_ROOT))`——**直接销毁子窗口根窗口，不经 WM_CLOSE**，引擎不知道子窗口被关，不触发全局 RunLoop 退出，主窗口与进程保持存活。（channel 用静态 vector 保活，避免 handler 被析构。）
2. **拦截系统 ×**（`playback_window.dart`）：子窗口 `_initWindow` 加 `setPreventClose(true)` + `windowManager.addListener(this)`；系统 × 被 window_manager 子类化拦截 → Dart `onWindowClose` → 统一走 `_close()`。
3. **统一关闭路径**：UI × / Esc / 主窗口退出时发来的 close，全部走 `_close()` = 通知主窗口复位 → 释放播放器 → `invokeMethod('destroySelf')` 原生销毁；Linux 等无原生通道的环境 catch 后回退 `windowManager.close()`。
4. 不再调用 `windowManager.destroy()` / `windowManager.close()`（Windows 主目标下）。

### 关键文件
- `flutter/windows/runner/flutter_window.cpp`：新增 `kotv_playback_native` 原生通道（destroySelf）
- `flutter/lib/desktop/playback_window.dart`：setPreventClose+WindowListener 拦系统 ×、`_close()` 走 destroySelf、dispose 移除 listener
- 验证：`flutter analyze` 0 error；`flutter test` 26/26 通过

## v4 修复（2026-10-29，Windows 实机验证后：子窗口不再遮挡主界面）

v3 构建后在网吧 Windows 实机（2560×1440）验证：**系统 × 已彻底修好**（点子窗口右上角 × → 子窗口消失、主窗口与引擎进程均存活 Responding=True，原生 DestroyWindow 方案实机有效）。同时定位到"弹出后主界面无法操作"的**直接原因**：子窗口创建默认 (10,10) 800×600，而 Dart 侧 `_initWindow` 里的 `windowManager.center()` 把窗口移到了**主窗口正中央**（实测子窗口 rect (373,351)-(1173,951)，正好叠在主窗口 (52,198)-(1403,1012) 的中心区域），大面积遮挡主界面——用户点"主界面"实际点在了子窗口上，表现为"弹出后主界面无法操作"。

### 修复

1. **原生通道新增 `moveToDefault`**（`flutter/windows/runner/flutter_window.cpp`）：`GetWindowRect` 取子窗口当前宽高，`GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 取屏幕尺寸，`SetWindowPos` 把子窗口放到**屏幕右侧中部**（x=屏宽-窗宽-60，y=垂直居中），`SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE` 不抢焦点不改变大小层级。
2. **`_initWindow` 去掉 `center()`**（`playback_window.dart`）：Windows 走原生 `moveToDefault` 定位到屏幕右侧；未注册原生通道的平台（Linux）catch 后回退 `center()`，行为不变。

## v5 修复（2026-10-29，根因级修复：播放器改为独立进程）

v4 实机交付后用户复测仍复现核心问题：**弹出独立播放窗口后，主窗口 Flutter 层冻结**——标题栏最小化/最大化可点（Win32 层活着），但界面选项全部点不动、两个窗口都无法关闭、只能杀进程。用户推测"主窗口的关闭和弹出子窗口关闭重复"，实为**同进程共享架构**的必然结果：

- desktop_multi_window 在同一进程里创建子窗口 engine；子窗口创建回调（挂在主窗口 platform thread 的方法通道派发栈上）里同步 `RegisterPlugins`（含 media_kit 加载 libmpv、初始化 mpv_handle），每次弹窗都阻塞主窗口 platform thread；
- media_kit/MPV 在子窗口解码/渲染与主窗口 Flutter engine 同进程抢 CPU/GPU，网吧机配置下主窗口 UI/光栅线程被拖死 → 界面点不动、关不掉、只能杀进程。

### 修复（架构级：播放器拆为独立进程 kotv-player.exe）

1. **新增 `flutter/lib/playback_main.dart`**：独立播放器进程入口（`kotv-player.exe`），`MediaKit.ensureInitialized` 后经本地 TCP IPC 等待主进程下发播放参数。
2. **新增 `flutter/lib/desktop/playback_ipc.dart`**：IPC 协议（127.0.0.1 随机端口 HTTP JSON）：主进程 `PlaybackIpcServer` 收播放器事件（ready/closed/error/switchEpisode）；播放器 `PlaybackIpcClient` 收主进程指令（play/close/focus）、上报事件。
3. **`playback_window.dart` 重写**：
   - `PlaybackWindow`（主进程侧）：不再用 `WindowController.create`，改为 `Process.start(kotv-player.exe)` + 环境变量 `KOTV_PARENT_PORT` 传 IPC 端口 + stdout 读 `KOTV_PLAYER_PORT=<port>` 握手 + HTTP 下发 play/close/focus；播放器进程退出（exitCode）自动复位主窗口。
   - `PlaybackWindowPage`（播放器进程侧）：去掉 desktop_multi_window 依赖（WindowMethodChannel/onWindowsChanged/_checkAlive/destroySelf 原生通道全删）；窗口定位用 `windowManager.setAlignment(centerRight)`（右侧中部，独立进程内安全）；关闭用 `setPreventClose(true)+onWindowClose → 上报 closed → windowManager.destroy()`（独立进程内 destroy 只退播放器进程，不再连退主窗口）。
4. **`main.dart`**：删除 MultiWindow 入口分支（`WindowController.fromCurrentEngine` 等），主程序只做主入口。
5. **`flutter/windows/runner/flutter_window.cpp`**：删除 `DesktopMultiWindowSetWindowCreatedCallback` 与 `kotv_playback_native`（destroySelf/moveToDefault）原生通道——不再需要共享进程子窗口。
6. **`pubspec.yaml`**：移除 `desktop_multi_window` 依赖（避免共享进程架构再次引入）。
7. **`scripts/package-flutter-windows.sh`**：主程序构建后追加 `flutter build windows --release --target=lib/playback_main.dart -o build/playback`，把播放器自包含目录（kotv-player.exe + dll + data）放入 `Release/kotv-player/`；zip 与 Inno 均递归打包该子目录。

### 效果
- 主窗口与播放器彻底隔离：播放器卡/崩/关都不影响主窗口 UI 与关闭；
- 系统 × / 窗口内 × / Esc 均只关播放器进程，主进程保持存活；
- 选集照旧：播放器上报 switchEpisode → 主窗口解析新集 URL → IPC 下发 play 切集。

### 验证
- `flutter analyze`：0 error（仅存量 info 级 deprecation）。

## v6.1 修复：主窗口启动被放到屏幕外不显示（2026-10-29）

用户安装 v6 后启动 KO，主窗口"打开不显示"（任务栏有 KO影视 图标但屏幕无窗口）。实机诊断（PowerShell user32）：

- kotv 进程存活且响应，主窗口句柄存在，IsWindowVisible=True；
- GetWindowRect = (-32000,-32000)–(-31680,-31720)，即尺寸仅 320×280、位于屏幕外；
- 处置：ShowWindow(SW_RESTORE)+SetWindowPos(80,60,1280,800)+SetForegroundWindow 后窗口恢复显示，主界面正常（"请先添加点播源"空源态）。

### 根因

主窗口位置/尺寸由 window_manager 持久化到 SharedPreferences（window_x/y/w/h），启动时 `waitUntilReadyToShow` 里 `setPosition(savedX, savedY)` 无条件应用。用户上次最小化/隐藏窗口时，Win32 把窗口挪到 (-32000,-32000) 哨兵坐标，`onWindowMove` 触发 `_persistWindowBounds()` 原样保存；本次启动 `setPosition(-32000,-32000)` 把窗口放到屏幕外，尺寸 320×280 亦为最小化时的异常值（恰为 kotvMinWindowSize）。

### 修复（flutter/lib/main.dart）

1. **保存端 `_persistWindowBounds`**：位置仅当 dx/dy 在 [-2000, 10000] 合理范围内才写入 window_x/y（哨兵/越界跳过，保留上次有效值）；尺寸仅当 w/h 在 (0, 10000] 才写入 window_w/h（最小化返回的 0/极小值不再覆盖）。
2. **启动端 `waitUntilReadyToShow`**：`setPosition` 前校验 savedX/savedY 同范围，不合法则忽略（交由 center 默认居中）。

### 验证

- `flutter analyze lib/main.dart`：0 error（仅存量 info 级 deprecation）。
- 待 CI 构建后实机复测：最小化再启动主窗口仍居中显示在屏幕内。
